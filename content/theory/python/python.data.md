## 1. Файлы, которые не помещаются в память

Правило: **никогда не читать файл целиком, если не знаешь его размера
наверняка.**

```python
# ПЛОХО: 8 ГБ в память
lines = open("events.log").readlines()

# Хорошо: построчно, память постоянна
with open("events.log", encoding="utf-8") as f:
    for line in f:
        process(line)
```

Файловый объект — итератор по строкам, и это самый дешёвый способ обработки
потока. Для CSV то же самое даёт `csv.reader`, для pandas — чтение порциями:

```python
for chunk in pd.read_csv("big.csv", chunksize=100_000):
    result = process(chunk)
```

**Кодировка задаётся явно.** Без `encoding="utf-8"` Python возьмёт системную,
и скрипт, работавший на Linux, упадёт на Windows или, хуже, прочитает
кракозябры. Русские данные регулярно приезжают в cp1251 — тогда это указывается
явно, а не выясняется опытным путём в проде.

**Пути через `pathlib`:**

```python
from pathlib import Path

for path in Path("data").glob("*.csv"):
    print(path.stem, path.stat().st_size)
```

## 2. CSV: три ловушки

CSV выглядит простым и таковым не является. Формат не стандартизован по-
настоящему, и каждая выгрузка приносит сюрприз.

**Ловушка 1: разделители внутри значений.**

```
id,name,comment
1,Иванов,"Купил 2 шт., доволен"
```

Запятая внутри кавычек — часть значения. Разбор через `line.split(",")`
сломается здесь молча, дав лишнюю колонку. **Поэтому CSV разбирают модулем
`csv`, а не строковыми операциями** — он знает про кавычки, экранирование и
переносы строк внутри значений.

**Ловушка 2: типы.** В CSV всё — строки. `"007"` превратится в число 7, если
доверить определение типа автоматике, и ведущие нули потеряются. То же с
телефонами, кодами регионов, артикулами.

```python
df = pd.read_csv("data.csv", dtype={"zip_code": str, "phone": str})
```

**Ловушка 3: пропуски.** Пустое поле, строка `NULL`, строка `NA`, строка `-` —
всё это может означать «нет значения». pandas по умолчанию считает пустыми
только часть из них, и `"NULL"` останется строкой посреди числовой колонки.

```python
df = pd.read_csv("data.csv", na_values=["NULL", "NA", "-", "не указано"])
```

Плюс отдельная беда: **`NaN` в pandas — это число с плавающей точкой**,
поэтому колонка целых чисел с пропусками автоматически становится вещественной,
и `id` превращается в `1.0`. Лечится типом `Int64` (с большой буквы), который
умеет хранить пропуски.

## 3. JSON

```python
import json

data = json.loads(text)                    # из строки
with open("f.json", encoding="utf-8") as f:
    data = json.load(f)                    # из файла

json.dumps(data, ensure_ascii=False, indent=2)   # обратно
```

`ensure_ascii=False` обязателен для русского текста: без него кириллица
превращается в `иван` — валидный JSON, но нечитаемый.

**JSON Lines** — формат выгрузок и логов: по одному объекту на строку. Его
можно обрабатывать потоково, в отличие от одного большого массива:

```python
with open("events.jsonl", encoding="utf-8") as f:
    for line in f:
        event = json.loads(line)
```

**Разворачивание вложенности.** Обычная задача: JSON от API вложенный, а
таблица нужна плоская.

```python
df = pd.json_normalize(
    data,
    record_path=["items"],          # список, который станет строками
    meta=["order_id", ["user", "id"]],  # поля верхнего уровня, которые тянем
    sep="_",
)
```

Что важно помнить: **вложенный список означает размножение строк**. Заказ с
тремя позициями превратится в три строки, и суммировать после этого сумму
заказа нельзя — она задвоится. Ровно та же ошибка, что задвоение при
соединении.

## 4. pandas: минимум и его границы

```python
df = pd.read_csv("sales.csv", parse_dates=["created_at"])

df.info()          # типы и пропуски — первое, что смотрят
df.describe()      # распределение числовых колонок
df.head()

df[df["amount"] > 0]                       # фильтр
df.groupby("city")["amount"].sum()         # агрегация
df.merge(users, on="user_id", how="left")  # соединение
df.assign(day=df["created_at"].dt.date)    # новая колонка
```

**Тип `object`** — то, что видно в `df.info()` чаще всего и что означает
«питоновские объекты, обычно строки». Он медленный и занимает много памяти:
каждое значение — отдельный объект в куче. Для колонок с повторяющимися
значениями есть `category`, экономящий кратно:

```python
df["city"] = df["city"].astype("category")
```

**`SettingWithCopyWarning`** — самая известная ловушка pandas. Она означает:
непонятно, меняешь ты исходный датафрейм или его копию. Возникает при цепочке
индексаций:

```python
# ПЛОХО: результат непредсказуем
df[df["amount"] > 0]["status"] = "ok"

# Хорошо: одна операция, явное указание строк и колонки
df.loc[df["amount"] > 0, "status"] = "ok"
```

**`apply` — не векторизация.** Он выполняет питоновскую функцию для каждой
строки и работает в десятки раз медленнее встроенных операций. Та же логика,
что с UDF в Spark: сначала ищем встроенный способ.

```python
df["total"] = df["price"] * df["qty"]      # быстро
df["total"] = df.apply(lambda r: ..., axis=1)  # медленно
```

**Где границы pandas.** Ориентир: данные должны помещаться в память с запасом
в несколько раз — промежуточные результаты операций тоже занимают место.
Дальше выбор:

- **потоковая обработка** порциями, если задача построчная;
- **SQL в базе**, если данные уже там: агрегировать миллиард строк на сервере
  дешевле, чем тащить их в ноутбук;
- **Spark или DuckDB**, если данных много, а базы нет.

Правило, которое стоит произнести на собеседовании: **не тащить данные к коду,
если можно принести код к данным.**

## 5. Parquet из Python

```python
df.to_parquet("out.parquet", compression="zstd", index=False)
df = pd.read_parquet("out.parquet", columns=["day", "amount"])
```

Два момента:

- **`columns=` — это и есть проекция**: читаются только указанные колонки, и
  на широкой таблице разница огромна.
- **`index=False`** обычно нужен: индекс pandas в файле — источник путаницы
  при чтении другими инструментами.

Схема, в отличие от CSV, хранится внутри файла, поэтому типы не теряются и
угадывать ничего не нужно. Обратная сторона: несовместимые схемы в одном
датасете дают ошибку при чтении.

## 6. Устойчивость к плохим данным

Обработка, которая падает на первой битой строке из миллиона, бесполезна;
обработка, которая молча их проглатывает, опасна. Правильный вариант —
**считать и сообщать**:

```python
bad = 0
for number, line in enumerate(f, start=1):
    try:
        record = parse(line)
    except (ValueError, KeyError) as exc:
        bad += 1
        logger.warning("строка %s не разобрана: %s", number, exc)
        continue
    yield record

if bad:
    logger.error("не разобрано строк: %s", bad)
```

Дальше решение принимается по доле: единицы битых строк из миллиона —
предупреждение, десять процентов — повод остановиться. Это тот же карантин, о
котором говорит узел про инциденты с данными, только на уровне файла.

## 7. Что ещё спросят

- **`csv.DictReader`** — читает строки словарями по заголовку, устойчив к
  перестановке колонок.
- **Разница `read_csv` и `read_table`** — только в разделителе по умолчанию.
- **`itertuples` против `iterrows`.** Второй создаёт Series на каждую строку и
  потому существенно медленнее. Но лучший вариант — не итерироваться вовсе.
- **`chunksize` и агрегаты.** Считая по порциям, нельзя просто усреднить
  средние: нужно накапливать сумму и количество, а делить в конце. Та же
  неаддитивность отношений, что в моделировании витрин.
- **Кодировка BOM.** Файл из Excel часто начинается с меток `﻿`, из-за
  чего первая колонка получает имя с невидимым префиксом. Лечится
  `encoding="utf-8-sig"`.

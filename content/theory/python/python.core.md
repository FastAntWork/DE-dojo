## 1. Имена, объекты и ссылки

В Python переменная — не коробка со значением, а **имя, привязанное к объекту**.
Присваивание не копирует объект, оно добавляет ещё одно имя.

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)  # [1, 2, 3, 4]
```

Список изменился «сам собой», потому что `a` и `b` — два имени одного объекта.

Разница проявляется только у **изменяемых** типов. Неизменяемые — числа, строки,
кортежи, `frozenset` — изменить нельзя в принципе: любая операция создаёт новый
объект.

```python
x = "abc"
y = x
y += "d"  # создан новый объект, x не тронут
```

Практическое следствие для работы с данными: **функция, принимающая список,
может его испортить**. Если она не должна этого делать, копию надо сделать явно —
`list(items)` или `copy.deepcopy` для вложенных структур. Обратное тоже верно:
если функция обязана изменить переданный объект, это должно быть видно из
названия.

## 2. Ловушка изменяемого аргумента по умолчанию

Классический вопрос на собеседовании, и он про то же самое:

```python
def add(item, target=[]):
    target.append(item)
    return target


add(1)  # [1]
add(2)  # [1, 2]  ← а ожидалось [2]
```

Значения по умолчанию вычисляются **один раз, при определении функции**, и
живут в её атрибуте `__defaults__`. Все вызовы делят один список.

Правильно:

```python
def add(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target
```

Та же ловушка со словарями, множествами и любыми изменяемыми объектами,
включая `datetime.now()` в аргументе по умолчанию — время зафиксируется на
момент импорта модуля.

> Источник: Python 3.12 Tutorial, «Default Argument Values» —
> https://docs.python.org/3.12/tutorial/controlflow.html#default-argument-values

## 3. Выбор структуры данных

Выбирается не по привычке, а по тому, какие операции будут частыми.

| Структура | Поиск по значению | Вставка в конец | Вставка в начало | Порядок |
|---|---|---|---|---|
| `list` | O(n) | O(1) | **O(n)** | сохраняется |
| `dict` | O(1) по ключу | O(1) | — | сохраняется с 3.7 |
| `set` | O(1) | O(1) | — | нет |
| `deque` | O(n) | O(1) | **O(1)** | сохраняется |

Три ошибки, которые заметно стоят на больших данных:

**Проверка вхождения в список.** `if item in big_list` — это линейный перебор.
На списке в миллион элементов внутри цикла по миллиону получается триллион
операций. Замена `set(big_list)` превращает проверку в константу — типичное
ускорение на порядки, и первое, что стоит искать в медленном скрипте.

**Вставка в начало списка.** `lst.insert(0, x)` сдвигает все элементы. В цикле
это квадратичная сложность. Нужен `collections.deque` с его `appendleft`.

**Конкатенация строк в цикле.** Строки неизменяемы, поэтому `s += "x"` каждый раз
создаёт новую строку. Правильно — накопить куски в список и один раз склеить
через `"".join(parts)`.

> Источник: Python 3.12 Tutorial, «Data Structures» —
> https://docs.python.org/3.12/tutorial/datastructures.html

## 4. Генераторы

Разница между списком и генератором — в том, когда вычисляются элементы.

```python
squares_list = [x * x for x in range(10_000_000)]  # ~400 МБ в памяти
squares_gen = (x * x for x in range(10_000_000))  # константа
```

Генератор считает элемент в момент запроса. Для инженера данных это не
оптимизация, а условие работы: файлы и выгрузки регулярно больше доступной
памяти.

```python
def read_errors(path):
    with open(path) as f:
        for line in f:  # файл читается построчно, не целиком
            if "ERROR" in line:
                yield line
```

Три свойства, которые надо помнить:

1. **Генератор одноразовый.** После полного прохода он пуст, второй цикл по нему
   не даст ничего. Нужен повторный проход — перечитывай источник или сохраняй
   в список осознанно.
2. **Функция с `yield` не выполняется при вызове.** Её тело начинает работать
   только при первом `next()`. Поэтому проверка аргументов внутри такой функции
   откладывается — ровно это проверяет ката к этому узлу.
3. **`itertools`** — стандартный набор для работы с потоками: `islice` вместо
   среза, `chain` вместо склейки, `groupby` для группировки подряд идущих.

## 5. Исключения

**Ловить надо по типу.** Голый `except:` перехватывает и `KeyboardInterrupt`, и
`SystemExit`, поэтому процесс перестаёт останавливаться по Ctrl+C, а настоящая
причина сбоя теряется:

```python
try:
    value = data["key"]
except KeyError:
    value = None
```

Если действительно нужно поймать всё — `except Exception`, с логированием и
повторным возбуждением.

**Порядок `try/except/else/finally`:**

- `else` выполняется, если исключения не было. Полезен, чтобы не заворачивать в
  `try` лишний код: в блоке остаётся только то, что может упасть.
- `finally` выполняется всегда — при исключении, при `return`, при `break`.
  Место для освобождения ресурсов.

**Но лучше `finally` — контекстный менеджер.** `with open(...)` закроет файл сам,
включая случай исключения. То же с соединениями к базе и блокировками. Если
пишешь `try/finally` для освобождения чего-либо — вероятно, нужен `with`.

**Не гасить исключения молча.** `except Exception: pass` — самый дорогой способ
спрятать ошибку: данные тихо теряются, а пайплайн зелёный. Если исключение
ожидаемо и обрабатывается — это должно быть видно в логе.

**Возбуждать своё, сохраняя причину:**

```python
raise ValueError(f"плохая строка: {line}") from exc
```

`from exc` сохраняет исходное исключение в цепочке — без него теряется место,
где всё началось.

> Источник: Python 3.12 Tutorial, «Errors and Exceptions» —
> https://docs.python.org/3.12/tutorial/errors.html

## 6. Что ещё спросят

Коротко о том, что примыкает к теме и встречается в вопросах:

- **Поверхностная и глубокая копия.** `copy.copy` копирует контейнер, но не
  вложенные объекты; `copy.deepcopy` — всё дерево.
- **`is` против `==`.** `is` сравнивает тождество объектов, `==` — значения.
  Для `None` пишут `is None`. Совпадение `is` для маленьких чисел и коротких
  строк — деталь реализации, полагаться на неё нельзя.
- **Аннотации типов** ничего не проверяют во время выполнения — это подсказка
  для читателя и для `mypy`. В вакансиях типизация упоминается как признак
  зрелой команды.

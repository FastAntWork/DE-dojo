# Инцидент: измерение с историей развалилось

**Понедельник.** Аналитик жалуется: отчёт по выручке в разрезе города даёт
цифры больше, чем отчёт без разреза. Разница плавает от периода к периоду.

Измерение `dim_customer` ведётся как SCD типа 2: у каждого клиента несколько
версий с интервалами действия. Загрузку правили дважды, каждый раз по-своему.

## Что есть на стенде

```sql
dim_customer (
    version_id,   -- суррогатный ключ версии
    customer_id,  -- естественный ключ клиента
    city, plan,   -- атрибуты, ради которых ведётся история
    valid_from,   -- дата начала действия версии
    valid_to,     -- дата окончания; NULL означает «действует сейчас»
    is_current    -- признак актуальной версии
)
```

Есть ещё таблица `_seed_versions` — снимок того, какие версии существуют.
**Она нужна проверке, трогать её не надо.**

## Договорённость об интервалах

Интервал полуоткрытый: версия действует **с `valid_from` включительно до
`valid_to` не включая**. Соединение с фактами выглядит так:

```sql
JOIN dim_customer d
  ON d.customer_id = f.customer_id
 AND f.event_date >= d.valid_from
 AND (d.valid_to IS NULL OR f.event_date < d.valid_to)
```

## Задача

Привести историю в порядок. Даты начала версий (`valid_from`) и атрибуты —
**источник истины, менять их нельзя**. Пересобрать нужно `valid_to` и
`is_current`.

## Что считается решённым

1. **История не потеряна.** Набор версий с их атрибутами совпадает с
   `_seed_versions`: ни одна не удалена, ни одна не добавлена, `valid_from`,
   `city` и `plan` не изменились.
2. **Интервалы не пересекаются.** Для любой даты у клиента действует не более
   одной версии — иначе соединение задваивает факты.
3. **В истории нет разрывов.** Между концом одной версии и началом следующей
   нет пропущенных дней — иначе события в разрыве не найдут версию вовсе и
   тихо выпадут.
4. **Ровно одна актуальная версия на клиента**, и это последняя по дате.
5. **У актуальной версии интервал открыт** (`valid_to IS NULL`), у остальных —
   закрыт.

## С чего начать

```sql
-- Посмотреть на одного клиента целиком
SELECT * FROM dim_customer WHERE customer_id = 1 ORDER BY valid_from;

-- Сколько клиентов имеет больше одной актуальной версии
SELECT count(*) FROM (
    SELECT customer_id FROM dim_customer
    WHERE is_current GROUP BY customer_id HAVING count(*) > 1
) x;
```

Дальше — понять, каким должен быть `valid_to`, если единственный источник
истины это `valid_from` соседней версии.
